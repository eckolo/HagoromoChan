# M14 履歴閲覧操作に応じた新着解除

## 定義

- ID: M14
- 優先度: 低
- 目的: 状態窓の「新着」の件数を、実際の履歴閲覧操作に応じて減らせるようにし、個別の小さい✓ボタンを逐一押す負担をなくす。
- 対象範囲: 受信済み回答の新着判定、履歴窓のアクティブ化および表示後の履歴スクロールによる新着解除、件数表示・永続化との整合、個別✓を必須としない操作設計。「新着」の表記は維持する。
- 対象外: 購読・配信・未回答要求の復旧（M06）、送信や回答の削除、起動管理（M08）、M03の完了状態の変更。
- 依存 ID: M03（完了済みの会話・履歴UI）。M06の新着／未回答状態定義との整合は設計時に確認する。M06の全機能への技術依存は未確定。
- 着手条件: 低優先度。ロードマップ上の先行・高優先度課題を考慮し、着手指示後に進める。
- 作業ブランチ（予定）: `milestone/M14-new-message-clearing`
- 分岐元 main SHA: 未着手・枝未作成。
- 担当: AI（着手指示後）。
- 根拠: 2026-11-25 ユーザー指示。「新着」の用語は維持し、その履歴窓が一度でもアクティブになる、またはその履歴窓表示後に履歴のスクロール操作が行われる程度のトリガで非新着扱いにする。小さいチェック窓の個別押下は面倒なので改善する。

| AC-03 | 新着解除後の件数と保存済み回答IDが整合し、再起動・同一回答の再取得で解除済みの新着が復活しない。通信上の未回答要求、会話本文、送受信・購読には影響しない。 | 回帰・再起動・実機確認 | 未確認 |

## 未確定事項

現行は単一の透過会話面に複数の履歴カードが含まれる。アクティブ化・スクロールをどの回答IDに適用するか、入力欄のみのフォーカス、既にアクティブな状態で追加受信した回答、ホイールや↑↓操作で終端に達した場合、長文の一部ページのみを表示した場合の扱いは設計時に確定する。新着を解除した対象の追跡には既存の永続化と重複排除を活用する方針。個別✓の残置・廃止は設計時の判断であり、現時点で削除を確定しない。
