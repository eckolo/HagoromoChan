# M14 履歴閲覧操作に応じた新着解除

## 定義

- ID: M14
- 優先度: 低
- 目的: 状態窓の「新着」の件数を、実際の履歴閲覧操作に応じて減らせるようにし、個別の小さい✓ボタンを逐一押す負担をなくす。
- 対象範囲: 受信済み回答の新着判定、履歴窓のアクティブ化および表示後の履歴スクロールによる新着解除、件数表示・永続化との整合、個別✓を必須としない操作設計。「新着」の表記は維持する。
- 対象外: 購読・配信・未回答要求の復旧（M06）、送信や回答の削除、起動管理（M08）、M03の完了状態の変更。
- 依存 ID: M03（完了済みの会話・履歴UI）。M06の新着／未回答状態定義との整合は設計時に確認する。M06の全機能への技術依存は未確定。
- 着手条件: 低優先度。ロードマップ上の先行・高優先度課題を考慮し、着手指示後に進める。
- 作業ブランチ（予定）: `milestone/M14-new-message-clearing`
- 分岐元 main SHA: 未着手・枝未作成。
- 担当: AI（着手指示後）。
- 根拠: 2026-11-25 ユーザー指示。「新着」の用語は維持し、その履歴窓が一度でもアクティブになる、またはその履歴窓表示後に履歴のスクロール操作が行われる程度のトリガで非新着扱いにする。小さいチェック窓の個別押下は面倒なので改善する。

## 表示・操作の境界

- 履歴の表示とウィンドウのアクティブ化は別。「新着」ボタンから開く場合は意図的に履歴をアクティブ化する。受信による履歴の自動表示は従来どおり非アクティブで、受信・再描画・入力専用のアクティブ化だけでは解除しない。入力と履歴が同じ窓にある場合、通常のアクティブ化で入力側にフォーカスがあるときも解除しない。
- ホイール・履歴の ↑↓ で表示されるページが実際に変わった場合に限って解除対象を判定する。入力側のホイール、終端やスクロール量不足による移動なし、表示領域不足でカードが出ない場合は解除しない。
- その操作時に表示対象だったページと、実際に窓内にレイアウトされたページが一致する回答だけを対象とする。あとから受信した回答、画面外または欠けたカードは対象外。長文の新着状態は回答単位のため、その回答の一ページを表示すれば一度だけ解除する。本文やページ操作には変更を加えない。
- 個別 ✓ は補助手段として残す。対象 ID の解除をまとめて処理し、既存の設定ストアに保存する。解除後に新着チェックを隠しても保持中のカードを作り直さず、本文のフォーカス・選択を壊さない。送受信・未回答要求・購読、M05 の取込回答は変更しない。

## Windows 隔離確認

別のローカル Git コピーを使い、`milestone/M14-new-message-clearing` の `scripts/Test-M14-HistoryRead.ps1` を実行する。Windows の .NET 10 SDK、Git、PowerShell 5.1 以上、既存のローカル NuGet パッケージフォルダーが必要（通常は `$env:USERPROFILE\.nuget\packages`、カスタム設定ならその場所）。不足パッケージのダウンロードや、プロキシ・実運用ポート・稼働中の SSP・購読・ランチャーには触れない。

```powershell
& .\scripts\Test-M14-HistoryRead.ps1 -PackageSource (Join-Path $env:USERPROFILE '.nuget\packages')
```

画面上の合成データと `[M14 TEST]` 表示がある試験用マスコットだけで、ガイドに従い、受信直後は 2 件、新着を消さず入力にフォーカス、表示中の A をアクティブ化して 1 件、履歴移動で B が見えて 0 件、再起動後も 0 件を確認する。各段階の保存済み ID を試験スクリプトが照合する。A と B が同時表示される画面では「表示していない B が残る」試験を成立扱いにせず、その時点の表示を報告する。終了時に試験プロセスのみを停止し、試験用一時フォルダーは確認用に保持する。正常結果は `M14_WINDOWS_HISTORY_OK`、失敗時は最後のフェーズと表示されたエラーを共有する（ログやトークンの転送不要）。

準備確認として、PowerShell 7.6.10 で構文解析エラーなし。Linux の `-NoDesktop` でオフライン復元・Release Relay・実 `/api/messages` と `/mcp` を用い、合成返信 2 件・独立した未回答 1 件・購読なしを照合し `M14_FIXTURE_OK`。同じ試験用ソースの Windows ターゲット Desktop をオフラインでビルド成功（警告／エラー 0）。Windows 上の `M14_WINDOWS_HISTORY_OK` は未確認。
