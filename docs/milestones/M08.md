# M08 起動・終了管理とスタートアップによる自動起動

## 定義

- ID: M08
- 優先度: 高（2026-11-25、ユーザー指示により中から変更）
- 目的: アプリのビルド・起動・停止・再起動を安全かつ容易に行えるように整理し、その運用を基盤として Windows の起動時（利用ユーザーのログオン時を想定）に羽衣ちゃんが自動起動できるようにする。
- 対象範囲（初期案）: ビルドと通常起動の分離、Desktop／Relay／トンネルの起動・停止・再起動、稼働確認・多重起動防止、ビルド時のファイルロック対策、スタートアップの有効化／無効化、認証情報の取り扱い、運用手順の整備。
- 対象外: M03 の表示・会話 UI の変更、M06 の詳細な通信診断、API キーの平文永続化、トンネルの無断起動・設定変更、無関係なプロセスの停止。
- 依存 ID・着手条件: M03 の基本 UI を先行。優先度は M03（最高）に次ぐ高とする。M03 の完了前に並行着手する場合はユーザーと合意する。M03 の Desktop 起動方式・データ保存・終了挙動との整合、Relay／トンネルの自動起動対象は設計時に確認する。
- 作業ブランチ（予定）: `milestone/M08-startup`
- 分岐元 main SHA: 未着手・枝未作成。
- 担当: AI（着手指示後）。
- 根拠: 2026-11-25 の追加登録指示、および M03 実機検証時の起動不具合を M08 に統合し優先度を高にする旨のユーザー指示。詳細は着手時に確定。

## 追加された課題と対処方針

M03 の実機検証で、Desktop を閉じてから `Start.ps1` を再実行した際にソリューション全体のビルドが発生し、Relay 側出力の `HagoromoChan.Contracts.dll` が稼働中の .NET Host にロックされ、MSB3026 の再試行と MSB3027／MSB3021 で失敗した。ログ上では Contracts と Desktop のビルドは成功。ユーザーによればロック元のプロセスを終了しても再起動した。トンネルが監視する stdio 子プロセスの再生成が有力だが、当該 PID の親・コマンドラインは実機で未照合。原因の識別と安全な運用の設計を本 ID で扱う。

- 通常の起動／再起動はビルド済み成果物を使用し、不要なビルドを実行しない。ビルドは明示操作に分離する。成果物がない場合や更新が必要な場合は、適切な手順を案内する。
- Desktop の再起動・UI 単体ビルド、Relay の再起動、トンネルの独立起動／停止、全体ビルドの責務と手順を分ける。
- 稼働中の DLL のロックを回避するため、ビルド対象・稼働プロセスを識別し、必要なら停止順序（トンネルを先に止め、監視下の子プロセスが再生成されないことを確認し、対象の Desktop／Relay を停止）を案内する。実行中の別アプリや会話処理を不用意に強制終了しない。
- 自動起動でも同じ起動手順を利用する。既存の「トンネルは別プロセス」要件を維持し、起動対象・キー取得方法を決める。データ、購読、認証情報を壊さず、不要な再登録・初期化を行わない。
- スクリプト分離（Build.ps1、Start.ps1、StartTunnel.ps1、Stop.ps1、StopTunnel.ps1 等）は設計候補。具体名・引数・互換性は着手時に決める。

現行の暫定回避は、ビルド済み成果物がある場合の `Start.ps1 -SkipBuild`、または M03 の Desktop.exe 単独起動。M03 の実機確認はこの経路で継続できる。恒久対処は M08 に集約する。
