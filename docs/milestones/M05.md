# M05 他会話の回答受信・会話管理基盤

## 定義

- ID: M05
- 優先度: 高（2026-11-26、ユーザー承認に基づき中から変更）。
- 目的: 既存のクラウドChat／クラウドWorkで発生した回答を羽衣ちゃんアプリに取り込み、受信元の会話を識別して保存・閲覧できる共通基盤を作る。
- 対象範囲: 公開された連携手段の実現可能性調査（受信と将来の送信先識別）、会話種別・安定したスレッド識別子・タイトル等の取得可能なメタデータ、受信を起点とする会話登録、回答の取得・重複防止・スレッド別履歴保存、既存Dot会話を維持する共通管理、受信元と本文を識別できる最小限の表示。通常のChatGPT上で発生した回答の取得を目標とし、明示転送が必要な方式と自動取得を区別する。
- 対象外: ローカルWork／ローカル実行環境固有の連携、複数スレッドの本格的な切替UI（M18）、他会話への発言送信（M19）、未受信会話の全件検索・自動検出、新規会話作成・プロジェクト選択、過去の全履歴同期、リッチコンテンツの専用表示、Work実行管理。既存Dotの送受信機能は維持する。
- 依存 ID・着手条件: M03・M04（完了済み）、M08の既存実行基盤を利用。M09とは受信確定・新着通知境界を調整し、同じファイルの同時編集を避ける。M09の完了を実現可能性調査の必須条件としない。次の高優先度の着手対象とする。
- 作業ブランチ: `milestone/M05-other-conversations`（既存予定名を維持）。
- 分岐元 main SHA: 作業ブランチ上の個別進捗および Git 履歴を参照。
- 担当: AI（着手後）、ユーザー（実アカウントでの許可・受入）。
- 承認根拠: 2026-11-26のユーザー承認（M05＋新規2件の分割、クラウドChat／Workに限定）、MGMT-17。

## 種別別の作業と操作条件（MGMT-23）

| 作業 | 順序 | 到達点と残条件 |
| --- | --- | --- |
| M05-Work：クラウドWorkの回答取得 | 先行 | 認可済みの対象回答を読み取れることは実証。次はSSPから選択し、最終回答1件を取得するひな型。接続・表示・保存の通し検証は別途実施する。 |
| M05-Chat：通常クラウドChatの本文取得調査 | 余力があるときに独立して並行 | 試験対象で回答IDは取得できたが、本文は省略された。全文を取得できる正式な経路を確認する。現状は定常実行・ユーザー作業待ちではない。 |

通常操作はSSP内で完結させる。会話や回答のID・URLの貼り付け、元会話への入力、元会話でのプラグイン選択は要求しない。Workひな型ができても通常Chatの条件は残る。初期の手動転送は経路確認のみであり、製品の操作仕様ではない。

## 初期工程と設計上の境界

1. クラウドChat、クラウドWorkについて、公式に利用可能な回答取得・転送・イベント等の手段、実行・承認条件、対象会話を継続して識別できる範囲、将来の送信経路の候補を種別ごとに調査する。API上の別会話を作る手段を既存ChatGPT会話へのアクセスと同一視しない。非公開内部API・認証回避・無断のブラウザ操作を前提としない。
2. 実アカウントでの小規模な受信検証を先に行い、自動取得／明示転送／非対応を区別する。任意のChat／Workの全回答を自動受信できるとは未確認。対応種別・必要操作・制約を提示し、当初目標が達成不能な場合はユーザーの合意を得てから対象・完了条件を見直す。
3. 受信元の種別・接続の信頼境界・安定した識別子を用い、会話タイトルだけで同一性を判定しない。将来M19で使用する返信先情報・取得できない場合の扱いを明示し、受信可能と送信可能を同一視しない。受信回答の識別・重複排除・保存・既存データの移行／互換性を設計する。スキーマ、API、受信イベントの詳細は着手時に決める。
4. 既存Dotの会話・履歴・購読・未回答・新着状態を保護する。受信した別会話の回答をDotへの依頼として扱わず、既存の購読やreplyを誤起動しない。最小限の受信確認表示を設け、横方向の選択・操作はM18へ引き渡す。

## 未確定事項

クラウド側の公開接続手段、安定した会話識別子・回答識別子・タイトル・送信先情報の取得範囲、受信の自動化・完了通知の粒度、対応可能種別、認可、スキーマと移行方式は未確定。受信と送信の両方を実現できることを前提にしない。新規のマイルストーンをさらに分ける場合はユーザーと合意してから管理登録する。
