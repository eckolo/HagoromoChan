# M21 アクション順序・中断・終了演出 v0.3

利用者確認を踏まえた採用仕様。M21は「いつ安全に再生するか」、M33は「何を選ぶか」、M10は「どこへどう移動するか」。

## 現行との差

基準は main `8cf38bdec54a5289aa58d5aa93214ca3863564ba` の動作コード。CharacterReactionState はポーズの順序値で再生中動作を上書きし、保留は1枠・2秒。開く／閉じる挨拶も反対の挨拶で取り消し得る。カーソルの向きは MainWindow.Reactions で描画に直接適用され、追い始め／追従の区別はない。管理起動時は操作の受理と管理プロセスからの停止通知の両方があり、現行は前者で描画を止め、後者で後片付けへ進む。この経路を維持しながら、正常停止通知でだけ演出を開始できるようにする。

## 再生段階と中断条件

| 動作 | 段階と通常の中断可否 | 優先イベント後 |
| --- | --- | --- |
| ジャンプ、送信受付、失敗、開閉の手振り | 開始から完了まで中断不可。現行尺を維持（約0.6～0.8秒）。 | 完了後に次の要求を再評価 |
| カーソル追従 | 追い始め（180ms）は中断不可、定常追従・戻りは中断可。位置更新で開始区間を再計時しない。 | リアクション後に現在のカーソルと有効条件を再取得。まだ有効なら最初から新しい追従を開始。中断地点や経過時間は保存せず、対象が離れたら開始しない |
| 思案・未読の待機などの繰り返し動作 | 静止している間と、描画で自然に区切れる境界だけ中断可。首かしげ・一瞥の途中は中断不可。 | 現在の会話状態から姿勢を決め直し、必要なら新しい周期の先頭から開始 |
| 静止待機・静止中の表情 | 思案・未読と同じフェーズ表に入れる。静止区間は可、まばたき等の短い表情の途中は不可。 | 現在の会話状態から通常姿勢を決め直す |
| アプリのお別れ | 正常終了専用。通常イベントでは中断しない。既存の閉じる仕草を初版では流用できるが、イベントIDと停止処理は別。 | 一度だけ後片付けへ |

静止・表情・繰り返し・有限動作は、中断可否・期間・素材の進み具合を持つ同じフェーズ表を使う。表示側がカーソル座標で再生予定を上書きすることはない。素材の段階が保証できないカスタムパックは先頭コマの静止区間を置き、短い一連だけ保護する。ループの区切れ目は「中立姿勢に戻った時点」など素材に合った明示的な境界とし、単なるフレーム更新や繰り返し周期全体の終端に固定しない。たとえば未読の7秒周期は静止時間の間いつでも譲り、一瞥中だけ戻りを待つ。思案の首かしげは中立に戻る地点で譲る。長い動作で反応が何秒も滞らないよう自然な境界を増やし、境界を保証できない素材は短い単位に分けるか静止待機を使う。遅い描画tickで境界を飛び越えても、区間をまたいだことを検出して次の周回を始める前に待ち行列に譲る。中断不可は通常の演出競合に限る。ドラッグ開始、明示的な動作OFF、OSセッション終了、異常、終了期限には従う。入力と会話は常に即時に処理し、演出の完了待ちで入力・送受信・未読表示を止めない。ドラッグは演出を即キャンセルして操作を優先する。メニューや押下の既存静止姿勢を保つ。実際のドラッグにならない短い押下／メニュー中は直前の有限動作を静止させ、解除時に同じ位置から再開する。保持は最長1秒とし、その間は経過を進めず、長時間の操作後に古い演出は再開しない。動作OFFでは待ち行列も捨てる。

## 待ち順と古くなった要求

- 再生中の短い動作は通常の要求に譲らない。受理できた要求は到着順。同じ取得で届いた複数の新着は従来どおり一度だけジャンプする。取得し直した同じ発言や履歴操作も再演しない。
- 未再生の連続新着は1件に集約する。開閉の挨拶は現在の表示と食い違えば捨てる（再生中なら完了させる）。未再生は4件、3秒まで。満杯時は古い挨拶を先に落とし、相互にまとめられない場合は新しい追加演出だけ見送る。期限と上限は演出だけに適用し、元の発言は一切捨てない。待ち時間は単調時計で測り、同じイベントの再送で更新しない。
- 例: 送信動作の途中に新着 → 送信動作を完了 → ジャンプ → 返信待ち／未読等その時点の姿勢。追い始めに新着 → 導入だけ待つ → ジャンプ → まだ条件を満たすなら追従を最初から開始。未読の一瞥中に送信受付 → 一瞥が正面に戻る → 送信受付。未読の静止区間なら待たない。

## 正常終了

- アプリの通常終了、または既存管理経路の正常停止通知で一度だけ終了モードへ入り、新規演出と未再生待ち行列を閉じる。再生中の中断不可区間だけ自然な区切れ目まで待つ（終端待ちの上限は0.8秒）、続いてお別れ約0.7秒。開始から後片付けへの上限は1.6秒とし、既存管理プロセスのDesktop終了猶予8秒は延ばさない。管理要求が拒否された場合に演出を行わない。
- 存在する描画素材と設定が有効で表示可能な場合だけ再生する。動作OFF、描画失敗、素材なし、タイムアウトは即または期限内に既存停止処理。OSログオフ・強制終了には演出を保証しない。管理停止通知が通常再起動と区別できない場合は同じ安全な正常停止扱いにする。アプリ内の明示的な再起動は観測できる場合にスキップし、STOP以外の司令を変更しない。
- 停止通知・閉じる操作の重複で再生も後片付けも増やさない。停止状態の枠内でだけ描画タイマーを維持し、表示・後片付け・管理経路の責務を混ぜない。

## 実装後の検証

仮想時計で有限動作の順番、導入境界、連続カーソル更新と新規追従の再開始、思案と未読の区切れ目、遅いtickが境界をまたいだときの優先引き渡し、複数新着と再取得、状態不一致、満杯と期限、操作・設定による例外、正常終了重複・失敗・期限を確認。通常のWindows起動で、送信と新着が接近、追従の最初からの再開始・非開始、思案と未読の切替、ドラッグで即操作、正常終了・動作OFFを確認する。実行結果は個別記録に分け、Windowsの見た目・通常終了を実機確認前に通過扱いにしない。
