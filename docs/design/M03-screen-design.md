## 1. 画面構成

### S01 通常状態

```text
        他のデスクトップ作業
                                [羽衣ちゃん]
```

背景・タイトルバーなし。透過立ち絵が単独で常駐する。通常の通信処理は継続する。必要な状態表示は従来の小型パネルを利用するが、一括非表示を明示した後は新しい返信または明示操作まで再表示しない。

### S02 会話状態

```text
  ╭────────────────────────────╮
  │ 羽衣ちゃん  日時          ⧉ │
  │ 回答全文（収まらない場合は頁） │────▶ [羽衣]
  ╰────────────────────────────╯
◀─╭────────────────────────────╮
  │ ユーザーの入力               │
  │  ↑ ↓ 入力頁/ショートカット  ➤ │
  ╰────────────────────────────╯
                       ╭────────╮
                       │ ↑ ↓ ×  │ ← 暗色・固定位置
                       ╰────────╯
```

図は羽衣ちゃんが右側の場合。ユーザーの発言と入力の尾は羽衣ちゃんと反対方向、羽衣ちゃんの回答の尾は羽衣ちゃん側。逆側・縦配置では向きを反転する。入力欄の「話しかける」見出しは設けない。会話履歴・入力の形状、背景色系統、縁取り、文字色を統一する。送信者識別のため紙色に小さな差を設ける。最下部は吹き出しとは別の暗色操作バーとし、同寸法の ↑・↓・× の3ボタンのみを置く。位置は文章量に依存しない。コピー、既読、通常送信は ⧉・✓・➤ で表示し、ツールチップとアクセシビリティ名に意味を明記する。エラー時の再試行など、意味が紛らわしい操作には必要な文字を残す。

### S03 履歴を上に展開

```text
   [古い回答の吹き出し]
   [古いユーザー発言の吹き出し]
   [最新の回答の吹き出し]
   [入力の吹き出し]             [羽衣]
                      [↑ ↓ ×]   ← 固定位置
```

初期の閲覧位置は最新発言（長文なら先頭ページ）。上操作で直前の発言またはページを上へ追加する。下操作で最古の表示を外し、より新しい範囲を表示する。画面に収まり切らないときは下端側の新しいカードを一時的に非表示にして古い側を読む。履歴データは削除しない。上下ボタンは連打・押し続けに対応し、会話面のホイールも同じ操作を行う。

右クリックの「話しかける」と「会話履歴」はチェック状態付きの独立トグル。ホバーの「会話」「履歴」も同じ動作とする。入力だけを開閉しても履歴の表示要求は変えず、履歴だけを開閉しても入力の表示要求を変えない。別の履歴ウィンドウは作らない。内部実装は一つの透過会話面を共有し、入力・履歴を別の表示状態として管理する。再表示時も下書きと履歴は保持する。

## 2. パーツと操作

| ID | パーツ | 挙動 |
| --- | --- | --- |
| P01 | 羽衣ちゃん | 透過立ち絵。両方閉じていれば左クリックで入力・履歴を開く。片方でも表示中なら左クリックで全周辺面を一括非表示。ドラッグは位置移動のみ。 |
| P02 | ホバーメニュー | 200msで表示、両領域から離脱して400msで非表示。明示的な一括閉じ直後、カーソルが本体に残っている間は再表示しない。 |
| P03 | 会話面 | 双方の発言を時系列の吹き出しで表示。本文に合わせて各カードの高さを計算。長文ページと履歴の移動は固定された上下操作に統一。 |
| P04 | ユーザー入力 | P03内の反対方向の吹き出し。見出しなし。Enterで改行、Ctrl+Enter／➤で全文送信。Esc・右クリック／ホバーの入力トグルで入力だけを閉じる（IME変換中は変換を優先）。 |
| P05 | 固定操作部 | 暗色・幅118 DIPのコンパクトな操作バーに32×30 DIPの ↑、↓、× を配置。履歴非表示時は上下ボタンを無効化。最新・履歴のみ／入力切替ボタンは廃止。本文の伸縮で操作ボタンを移動させない。 |
| P06 | 状態・エラー | 本体または近接ホバー枠を基準に配置し、モニターの離れた四隅には退避しない。観測可能な状態・再試行・未読の導線を維持。長い診断文は⧉で全文取得できる。M06の詳細診断は対象外。 |
| P07 | 右クリックメニュー | 話しかける（独立チェック）、会話履歴（独立チェック）、最前面、表示サイズ（小120、中180、大・標準260 DIP）、位置初期化、終了。近接状態枠を物理的に表示できない場合は状態のコピー・利用可能な再試行／未読表示をここから操作する。 |

## 3. 表示と通信状態の分離

- キャラ左クリック（入力・履歴が両方閉じている）: 最新発言と入力を開き、明示操作として入力フォーカスを取得する。
- キャラ左クリック（入力または履歴が一つでも開いている）／会話面の×: 吹き出し、入力、ホバー、状態、コンテキストメニューを一括で隠す。ユーザーがすぐデスクトップの別作業へ戻れるようにする。履歴・下書き・送信受付確認・返信待ち・未読状態は取り消さない。
- 独立トグル: 話しかけるは入力だけ、会話履歴は履歴だけを反転する。新たな入力表示の明示操作時にのみフォーカス取得を試みる。片方だけ開いた状態から本体クリックでは一括閉じする。
- 受信: 新しい返信なら履歴だけを自動表示できるが入力の表示状態は変更せず、フォーカスも奪わない。古いページ閲覧中は閲覧起点を勝手に変えず、新着件数を更新する。明示的に閉じた後、同じ未読の再通知や定期ポーリングによる状態パネル再出現は行わない。
- 未読: 既存のID単位・保存済みチェックポイントを維持する。表示や一括閉じでは既読にしない。各回答カードの ✓ で明示確認する。未読がある場合は近接状態枠に新着件数と未読への導線を残す。最下部の最新ボタンは設けず、通常の履歴移動は上下操作で行う。
- 送信: 既存のrequest ID・保存・再試行を維持し、表示ページではなく編集した下書き全文を送信する。過去の表示位置は返信先IDを変えない。ローカル受付を確認したら入力をクリアして最新へ移動する。
- IME変換中は編集ページの再分割を行わない。変換確定後に計測・ページ調整を行う。通常のキーボード操作で誤送信しないことを検証する。

## 4. 文章量と有限画面の扱い

**会話本文・入力にはスクロールバーを設けない。** WPFのテキストコントロールを実際の表示幅で計測し、本文全体が収まる高さにする。幅は利用可能な側の空きに応じ最大620 DIP。画面作業領域の上限まで利用し、旧45%高さ制限を廃止する。

ただし画面の物理寸法を超える一つの本文を一窓へ全部同時表示することはできない。以下の規則で対応する。

- 回答／過去発言が表示可能高さを超える場合は、元本文を保持したまま文字要素境界でページ分割。日時とページ番号を表示し、上下操作で全ページを閲覧する。コピーは分割前の全文。
- 下書きが一ページに収まらない場合は、ページ分割された入力を編集する。下書きの全体文字列を保持し、入力内の↑↓で前後ページへ移動する。入力欄のスクロールバーは無効。IME変換中は再分割を保留するため、ごく短時間の変換表示の超過は実機確認対象。長文下書きの選択・undoはページ内に限られ、全文を送信する。
- 画面に収まらない履歴カードは表示範囲外へ一時退避する。各表示カードに本文の欠落・切り捨て・内側スクロールが発生しないことを実機で確認する。極端に小さい作業領域では右クリックの独立トグルで片方を閉じて領域を確保する。必要な領域が確保できない場合は表示を保留し、表示要求・下書き・元の履歴は勝手に変更しない。すべての文字を同時に表示する要求とは区別する。
- 診断・障害の長い文言は会話本文とは別の扱いとし、状態パネルの詳細コピーで全文を取得する。

## 5. 固定操作部・画面配置

キャラクター座標とモニターの作業領域から `ConversationZone` を決定する。左右の空きが十分なら広い側へ展開し、狭い場合は上下に展開する。会話面は表示中、領域の物理ピクセル矩形を固定する。内容だけを下端に整列し、各吹き出しを必要な高さで描く。操作バーは会話領域の本体側の固定下端に配置する。履歴件数、文章長、入力行数の変化で移動しない。キャラクター移動、DPI・モニター作業領域の変更時に配置を再計算する。負座標とマルチモニターも対象。

通常時は立ち絵以外の広い透明ウィンドウを表示しない。v2.1では会話表示中に限り、会話領域全体の固定された透過ウィンドウを使用する。可視の吹き出し・操作バー以外に不透明な背景を描かない。これにより履歴増減時のHWNDのサイズ変更をなくす。広がった完全透過部分で背後の操作ができるかはWindows実機で確認する。

### v2.1 描画の修正

v2.0は表示カードのキーが変わるたびに履歴StackPanelのChildren.Clearと全カード再生成を実行し、カード合計高に合わせて会話HWNDのサイズ・位置も変更していた。これらはユーザーのちらつき報告と整合する有力な原因。v2.1では発言ID・ページ範囲・表示条件によるキーで差分を計算し、消えるカードだけをRemoveAt、加わるカードだけをInsertする。残るカードのUIElementとTextBoxは保持する。表示条件や既読状態が実際に変化したカードだけ作り直す。同じ矩形へのWin32位置変更と強制レイアウトを省き、尾の形状も向きが変わらなければ更新しない。OS描画レベルのちらつき解消は未確認。

### v2.1 補助枠配置の修正

v2.0のFreePositionは空きがなければモニターの四隅を順に検索し、会話面の可変矩形を障害としていた。補助枠が左上に孤立したり会話量に伴って移動する事象のコード上の原因として確認。v2.1は本体／モニターを起点に会話の固定領域とホバー予定枠を予約し、近傍の上下左右だけを検索する。状態枠の候補は本体または近接ホバー枠に接する位置（8 DIP程度の間隔）に限定する。余裕がない場合は会話領域との重なりを許容して近傍を優先、両補助枠が共存できなければ状態枠を優先する。近傍に物理的に収まらなければ補助枠は隠し、右クリックで操作を提供する。画面四隅へは飛ばさない。初回表示・DPI変更時の物理座標と見た目は実機確認事項。

## 6. 画像素材・サイズ

高解像度の透過立ち絵を [Assets](../../src/HagoromoChan.Desktop/Assets/README.md) に配置した。旧123×180px素材からの拡大ではなく、先行全身原画から作成し直す。標準は旧大260 DIP。小120、中180。旧標準180を保存していた設定は初回v2読み込み時に260へ移行し、それ以降に明示した中180は維持する。

表示サイズは物理ピクセルで元画像幅・高さを上限とし、縦横比を維持して縮小する。DPI倍率が大きい場合も原寸以上に拡大しない。任意の透過PNGのローカル差替えを引き続き利用できる。

## 7. 実装分割・検証

- DesktopPanels: 会話面、固定操作部、履歴スタック、入力ページ、ホバー・状態。
- TextPaging: 原文を保つ文字要素境界分割、編集スライス置換、履歴前後移動と表示範囲計算、独立表示状態、保持カードの差分計画。
- OverlayLayout / NativeDesktop: 固定アンカー領域、補助枠近接候補・幅、物理矩形の差分更新、元画像の物理ピクセル上限。
- MainWindow.Conversation / Interaction: 既存送受信の接続、未読、クリックによる一括開閉。
- DesktopPreferences / MascotArtwork: 標準サイズ移行、設定保存、透過PNGの読み込み。

検証手順は [M03 実機確認手順](../operations/M03-verification.md) を参照する。v2.0の実機レビューは受領済み。v2.1実装候補はSDK・Windows GUIのない環境で作成し、C#ビルド・回帰実行・Windows実機確認は未実施。M03の完了判定・main統合は実機検証後。
