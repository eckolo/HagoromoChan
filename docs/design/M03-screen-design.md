## 1. 画面構成

### S01 通常状態

```text
        他のデスクトップ作業
                                [羽衣ちゃん]
```

背景・タイトルバーなし。透過立ち絵が単独で常駐する。通常の通信処理は継続する。必要な状態表示は従来の小型パネルを利用するが、一括非表示を明示した後は新しい返信または明示操作まで再表示しない。

### S02 会話状態

```text
  ╭────────────────────────────╮
  │ 羽衣ちゃん  日時       コピー │
  │ 回答全文（収まらない場合は頁） │────▶ [羽衣]
  ╰────────────────────────────╯
◀─╭────────────────────────────╮
  │ ユーザーの入力               │
  │  ↑ ↓ 入力頁/ショートカット 送信│
  ╰────────────────────────────╯
  ╭────────────────────────────╮
  │ ↑     ↓    最新/新着   入力  × │ ← 固定位置
  ╰────────────────────────────╯
```

図は羽衣ちゃんが右側の場合。ユーザーの発言と入力の尾は羽衣ちゃんと反対方向、羽衣ちゃんの回答の尾は羽衣ちゃん側。逆側・縦配置では向きを反転する。入力欄の「話しかける」見出しは設けない。会話履歴・入力の形状、背景色系統、縁取り、文字色を統一する。送信者識別のため紙色に小さな差を設ける。上下操作、最新・新着、入力表示切替、閉じるの位置は文章量では変えない。

### S03 履歴を上に展開

```text
   [古い回答の吹き出し]
   [古いユーザー発言の吹き出し]
   [最新の回答の吹き出し]
   [入力の吹き出し]             [羽衣]
   [↑ ↓ 最新/新着 入力 ×]   ← 固定位置
```

初期の閲覧位置は最新発言（長文なら先頭ページ）。上操作で直前の発言またはページを上へ追加する。下操作で最古の表示を外し、より新しい範囲を表示する。画面に収まり切らないときは下端側の新しいカードを一時的に非表示にして古い側を読む。履歴データは削除しない。上下ボタンは連打・押し続けに対応し、会話面のホイールも同じ操作を行う。

右クリック／ホバーの「会話履歴」は同じ会話面を履歴中心（入力を閉じる）で開く。別の履歴ウィンドウは廃止する。入力を開き直す場合は同じ面に戻り、下書きと会話履歴は保持する。

## 2. パーツと操作

| ID | パーツ | 挙動 |
| --- | --- | --- |
| P01 | 羽衣ちゃん | 透過立ち絵。左クリックで会話面を開く。開いていれば左クリックで全周辺面を一括非表示。ドラッグは位置移動のみ。 |
| P02 | ホバーメニュー | 200msで表示、両領域から離脱して400msで非表示。明示的な一括閉じ直後、カーソルが本体に残っている間は再表示しない。 |
| P03 | 会話面 | 双方の発言を時系列の吹き出しで表示。本文に合わせて各カードの高さを計算。長文ページと履歴の移動は固定された上下操作に統一。 |
| P04 | ユーザー入力 | P03内の反対方向の吹き出し。見出しなし。Enterで改行、Ctrl+Enter／送信で全文送信。Esc／入力切替で入力だけを閉じる。 |
| P05 | 固定操作部 | 会話表示領域の下端を基準に ↑、↓、最新／新着、入力切替、× を配置。本文の伸縮で操作ボタンを移動させない。 |
| P06 | 状態・エラー | 既存中継で観測可能な状態・再試行を維持。長い診断文はコピーで全文取得できる。M06の詳細診断は対象外。 |
| P07 | 右クリックメニュー | 会話、会話履歴、最前面、表示サイズ（小120、中180、大・標準260 DIP）、位置初期化、終了。 |

## 3. 表示と通信状態の分離

- キャラ左クリック（会話面が閉じている）: 最新発言と入力を開き、明示操作として入力フォーカスを取得する。
- キャラ左クリック（会話面が開いている）／会話面の×: 吹き出し、入力、ホバー、状態、コンテキストメニューを一括で隠す。ユーザーがすぐデスクトップの別作業へ戻れるようにする。履歴・下書き・送信受付確認・返信待ち・未読状態は取り消さない。
- 受信: 新しい返信なら自動表示できるがフォーカスを奪わない。古いページ閲覧中は閲覧起点を勝手に変えず、新着件数を更新する。明示的に閉じた後、同じ未読の再通知や定期ポーリングによる状態パネル再出現は行わない。
- 未読: 既存のID単位・保存済みチェックポイントを維持する。表示や一括閉じでは既読にしない。各回答カードの「既読」で明示確認、最新／新着ボタンで最初の未読または最新発言へ移動できる。
- 送信: 既存のrequest ID・保存・再試行を維持し、表示ページではなく編集した下書き全文を送信する。過去の表示位置は返信先IDを変えない。ローカル受付を確認したら入力をクリアして最新へ移動する。
- IME変換中は編集ページの再分割を行わない。変換確定後に計測・ページ調整を行う。通常のキーボード操作で誤送信しないことを検証する。

## 4. 文章量と有限画面の扱い

**会話本文・入力にはスクロールバーを設けない。** WPFのテキストコントロールを実際の表示幅で計測し、本文全体が収まる高さにする。幅は利用可能な側の空きに応じ最大620 DIP。画面作業領域の上限まで利用し、旧45%高さ制限を廃止する。

ただし画面の物理寸法を超える一つの本文を一窓へ全部同時表示することはできない。以下の規則で対応する。

- 回答／過去発言が表示可能高さを超える場合は、元本文を保持したまま文字要素境界でページ分割。日時とページ番号を表示し、上下操作で全ページを閲覧する。コピーは分割前の全文。
- 下書きが一ページに収まらない場合は、ページ分割された入力を編集する。下書きの全体文字列を保持し、入力内の↑↓で前後ページへ移動する。入力欄のスクロールバーは無効。IME変換中は再分割を保留するため、ごく短時間の変換表示の超過は実機確認対象。長文下書きの選択・undoはページ内に限られ、全文を送信する。
- 画面に収まらない履歴カードは表示範囲外へ一時退避する。各表示カードに本文の欠落・切り捨て・内側スクロールが発生しないことを実機で確認する。極端に小さい作業領域では入力／履歴のみを切替、収まる領域を確保できない場合は案内を表示する。すべての文字を同時に表示する要求とは区別する。
- 診断・障害の長い文言は会話本文とは別の扱いとし、状態パネルの詳細コピーで全文を取得する。

## 5. 固定操作部・画面配置

キャラクター座標とモニターの作業領域から `ConversationZone` を決定する。左右の空きが十分なら広い側へ展開し、狭い場合は上下に展開する。会話面は領域の下端をアンカーとし、各吹き出しは内容の高さに応じて上へ伸びる。操作バーは常に同じ下端・横位置、同じ高さ。履歴件数、文章長、入力行数の変化で動かない。キャラクター移動、DPI・モニター領域の変更時のみ配置を再計算する。負座標とマルチモニターも対象。

通常時は立ち絵以外の広い透明ウィンドウを表示しない。会話面は必要なカードの合計高さをもつ透明ウィンドウで、カード間の余白には不透明な背景を描かない。透明部分のクリック透過とフォーカス制御はWindows実機確認事項。

## 6. 画像素材・サイズ

高解像度の透過立ち絵を [Assets](../../src/HagoromoChan.Desktop/Assets/README.md) に配置した。旧123×180px素材からの拡大ではなく、先行全身原画から作成し直す。標準は旧大260 DIP。小120、中180。旧標準180を保存していた設定は初回v2読み込み時に260へ移行し、それ以降に明示した中180は維持する。

表示サイズは物理ピクセルで元画像幅・高さを上限とし、縦横比を維持して縮小する。DPI倍率が大きい場合も原寸以上に拡大しない。任意の透過PNGのローカル差替えを引き続き利用できる。

## 7. 実装分割・検証

- DesktopPanels: 会話面、固定操作部、履歴スタック、入力ページ、ホバー・状態。
- TextPaging: 原文を保つ文字要素境界分割、編集スライス置換、履歴前後移動と表示範囲計算。
- OverlayLayout: 固定アンカー領域・元画像の物理ピクセル上限。
- MainWindow.Conversation / Interaction: 既存送受信の接続、未読、クリックによる一括開閉。
- DesktopPreferences / MascotArtwork: 標準サイズ移行、設定保存、透過PNGの読み込み。
