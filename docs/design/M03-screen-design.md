## 1. 画面構成・ワイヤーフレーム

図中の枠は表示パーツを表す。画面全体の背景・枠は実際には表示しない。立ち絵の透明部分をクリック透過させる。

### S01 通常時
```text
 デスクトップ・他アプリの上

                                  [P01 立ち絵]
```
キャラクター単独。操作メニュー・吹き出し・入力欄は非表示。応答待ち等の通知が必要な場合のみ P06 を表示する。通常時に架空の挨拶や通信内容を生成しない。

### S02 ホバー
```text
            [会話] [履歴] [設定]  P02
                   [P01 立ち絵] ← マウス
```
非アクティブのコンパクトな操作メニュー。キャラクターからボタンに移動するための猶予を設ける。ホバーだけではフォーカスを奪わない。

### S03 会話・入力
```text
              ╭──────────────────────────╮
              │ 前へ  1/2  次へ  新着  × │
              │ P03 回答本文（スクロール）│
       ◀──────╰──────────────────────────╯
 [P01 立ち絵]
              ╭──────────────────────────╮
              │ P04 羽衣ちゃんへの発言    │
              │                  [送信]  │
              │ Ctrl+Enter で送信        │
              ╰──────────────────────────╯
```
入力を開いた際に直近の回答があれば表示する。回答がない場合は吹き出しを省略する。既存履歴の全文は P05 から開く。吹き出しを閉じる操作と入力欄を閉じる操作は独立させる。

### S04 新着受信・入力なし
```text
              ╭──────────────────────────╮
              │ P03 新着              ×  │
              │ 羽衣ちゃんの回答本文     │
       ◀──────╰──────────────────────────╯
 [P01 立ち絵]
```
受信時に表示するが、他アプリの入力フォーカスを奪わない。表示中の古い回答を読んでいる場合は本文を突然置換せず、新着へ移動する操作を出す。通常の会話返信を対象とし、Dot 自発発言の経路は M04。

### S05 履歴
```text
              ┌─ 会話履歴 ─────────── × ┐
              │ 自分  10:30  発言本文    │
              │ 羽衣  10:30  回答本文    │
 [P01 立ち絵] │ 自分  10:32  発言本文    │
              │ 羽衣  10:32  回答本文    │
              │       [最新へ] [コピー]  │
              └──────────────────────────┘
```
必要時だけ表示する補助パネル。全履歴の時系列、日時、送信者、テキストの選択・コピーを維持する。既読を含む過去の回答はここから確認する。

### S06 設定・コンテキストメニュー
```text
              ┌───────────────────┐
              │ 会話 / 履歴        │
              │ 最前面表示   ✓    │
 [P01 立ち絵] │ 表示サイズ   標準 │
              │ 表示位置を初期化  │
              │ 設定 / 終了       │
              └───────────────────┘
```
右クリック等から必ず終了手段に到達できる。設定 UI とトレイ表示は案。設定は最前面、サイズ・位置の基本項目に限定する。

## 2. パーツ仕様

| ID | パーツ | 表示 | 操作・振る舞い |
| --- | --- | --- | --- |
| P01 | 羽衣ちゃん本体 | 原則常時 | 透過立ち絵。左クリックで会話入力を開く。ドラッグで位置移動。右クリックでメニュー。素材は後で決定。 |
| P02 | 操作メニュー | ホバー時 | 会話・履歴・設定。クリックで該当パネルへ。ホバー離脱で閉じる。単なるホバーではフォーカスを取得しない。 |
| P03 | 回答吹き出し | 会話時・新着時 | 本文と前後移動・新着・閉じる。短文は内容に合わせる。長文は上限サイズで内部スクロール。テキスト選択・コピー可。 |
| P04 | 入力欄 | 明示的な会話操作時 | 複数行入力。送信ボタンまたは Ctrl+Enter で送信。Enter は改行。IME 変換中は送信しない。閉じても未送信下書きを保持する（少なくとも同一プロセス内）。 |
| P05 | 会話履歴 | 明示的な履歴操作時 | 既存履歴を表示する。読み返し中のスクロール位置を尊重し、新着時は最新へ移動する操作を出す。 |
| P06 | 簡易状態・エラー表示 | 必要時のみ | 送信中・応答待ち・送信失敗・配信失敗・新着件数など、現行機能で根拠のある状態を表示。既存の再試行操作を維持。常時の接続バッジは不要。詳細な診断は M06。 |
| P07 | 設定・右クリックメニュー | 明示操作時 | 最前面、サイズ・位置、終了等。クリック外でメニューを閉じても入力や回答を消さない。 |
| P08 | トレイ操作 | 提案 | 表示の復帰・終了を提供する補助的な入口。設定が必要な場合に検討。常駐化そのものと M08 のログオン時自動起動は区別する。 |

## 3. 操作・状態遷移

キャラクターの状態（通常、ホバー、ドラッグ）、会話パネルの状態（回答、入力、履歴、設定の表示・非表示）、通信の状態（待機、送信中、応答待ち、失敗等）は分離する。表示中に別の状態が重なり得るため、一個の排他的な画面状態にしない。

| 発生条件 | 遷移・操作 | フォーカス等の制約 |
| --- | --- | --- |
| 起動・位置復元 | S01、履歴取得を開始。 | 古い履歴を新着として一斉表示しない。 |
| 本体上でホバーが約200ms継続 | P02 を表示 | フォーカス取得なし。 |
| 本体からメニューへ移動 | P02 維持 | 透明な広い当たり判定を設けない。 |
| 本体・メニューの両方から離脱 | 約400ms 後に P02 非表示 | 会話パネルは閉じない。 |
| 本体左クリック／会話ボタン | P04 を開き、P03 に直近回答があれば表示 | 明示操作のため入力フォーカス取得可。既に入力欄が開いていればフォーカスだけ移動。 |
| マウス押下後に OS のドラッグ閾値超過 | 位置移動 | クリックによる会話開始を抑止。各表示パーツは追従。 |
| 右クリック | P07 を表示 | 左クリックの処理とは分離。 |
| 送信ボタン／Ctrl+Enter | 現行の送信処理を使用 | IME 変換中・二重送信防止を維持。ローカル受付結果に応じて入力をクリア。 |
| 受付済み、まだ回答なし | P06 に応答待ちを表示可能 | 通信受付と実際の応答到着は別。入力を閉じても処理は継続。 |
| 回答到着 | S04。入力中なら入力欄を維持し、表示中の旧回答は置換せず新着通知 | 自動フォーカス移動なし。 |
| 回答の ×／既読操作 | P03 非表示、確認済みを記録 | 入力欄・履歴・通信のキャンセルではない。未読が複数なら件数を残す。 |
| 入力欄の ×／Esc | P04 非表示 | IME変換中の Esc は変換キャンセルを優先。入力を破棄・送信しない。 |
| 履歴・設定の × | 対象のパネルだけ閉じる | 本体は残る。 |
| 送信失敗／配信失敗 | P06 に理由・再試行 | 下書き・受付確認・既存IDを保持。無関係な通信は中断しない。 |
| 終了 | すべての UI を閉じ、必要な保存を行う | Relay/Tunnel の終了管理を勝手に変更しない。 |

ホバー時間は暫定値。回答吹き出しは初期案ではタイマーで自動消去せず、明示的に閉じる。複数新着は ID/Sequence で区別し、件数を表示しながら順次閲覧できる。初回起動時は取得した既存履歴を通知基準とし、以降は保存した確認済み位置・受信済み ID と照合する。起動中だけでなく再起動後の二重通知・未読消失を検証対象とする。自動表示だけで確認済みにはしない。

既存送信仕様は送信時の最新 assistant メッセージへの継続であり、古い回答の閲覧だけで暗黙に宛先を切り替えない。最新回答が入力中に到着した場合は新着を示す。任意の過去回答を指定して分岐・返信する機能は本案に含めない。

## 4. レイアウト・視認性

数値は DIP（96 DPI 基準）での暫定案。画像のピクセルサイズとは区別する。

| 項目 | 初期値・制約 |
| --- | --- |
| キャラクター | 高さ180 DIP、縦横比維持。変更可能。初回は主モニター右下の作業領域に余白16 DIP。 |
| 操作メニュー | キャラクター上部を優先。ボタン幅は内容に応じ、タスクバー等と重ねない。 |
| 回答吹き出し | 幅240～420 DIP程度、最大高さは作業領域の45%程度を目安。実際には画面内の利用可能領域を優先。 |
| 入力欄 | 吹き出しと同程度の幅。最小2～3行、最大6行程度から内部スクロール。 |
| 履歴・設定 | 独立の補助パネル。会話パーツとの同時表示は必要時のみ。 |
| 配置 | キャラクター左右の空きが大きい側を選ぶ。収まらなければ上・下に再配置。端のときは吹き出しの尾の位置も反転。 |
| 移動 | 本体位置を基準に各パーツを追従させる。複数モニター、DPI変更、負座標、モニター切断後も画面内へ補正。 |

先行外観サンプルの装飾は参考とし、情報の可読性・操作範囲を優先する。立ち絵以外に常時の面・フレームを描画しない。吹き出しや入力・メニューは個別の背景を持ってよい。透明部分を含む大きな常時最前面ウィンドウで他アプリの操作を遮断しない。表示の最前面設定は現行機能を引き継ぐ。実際の OS ウィンドウ分割は実装設計で決める。

## 5. 現行機能との整合・将来拡張

現行 Desktop の MainWindow.xaml / MainWindow.xaml.cs、Contracts/Messages.cs を基準とする。送信ID・継続先・ページング・重複排除・受付確認・PendingMessageStore・送信制御・IME対策・再試行・スクロール・コピーを保持する。プレーンテキスト表示を基準とし、Markdown やリッチレンダリングをこの段階の必須条件にはしない。メッセージ通信とパネル表示は分離し、閉じたパネルが受信処理を終了させない。

将来の M09 では会話・マウスイベントを反応アクションへ渡す境界、M10 では本体の位置を変更する手段を使う想定。M03 は静止立ち絵・手動ドラッグで成立させ、反応モーションや自律移動の実装は行わない。M08 の起動設定・プロセス起動管理、M04・M05 のメッセージ経路、M06 の診断強化も独立させる。

## 6. 確認事項と検証計画

ユーザー確認が必要な設計項目: ホバー／左クリック／右クリックの役割、吹き出し・入力欄・履歴の分離、受信時の自動表示・明示閉じ、サイズや配置の初期案。画像素材の確定、保存設定の詳細、実装方式は後続作業。

暫定 AC-01～03 に加え、以下を実装時の確認項目にする。
- 通常時の透過表示・クリック透過・ドラッグとクリックの区別・画面内補正
- ホバー時に他アプリのフォーカスを奪わずメニューへ到達できること
- 送信・返信・複数新着・長文・履歴参照・再試行・IME変換・下書き保持
- 受信時にフォーカス・読み返し位置を奪わないこと、再起動後に既存履歴を無条件で再通知しないこと
- 設定・終了操作への到達性、表示パーツを閉じても通信処理が継続すること
- 複数モニター／DPI／タスクバーとの干渉

本版は画面設計のみ。アプリコード・素材・設定は未変更、ビルド・実機検証は未実施、AC-01～03 は未達成のまま。ユーザー確認後、設計を確定し実装に進む。
