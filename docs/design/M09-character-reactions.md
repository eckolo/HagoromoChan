## 2. 状況とアクションの対応

既存素材の英語名を参照名として使用する。括弧内の時間は初期調整値であり、Miniから取得した元の再生時間ではない。

動きを無効化できる設定とWindowsのクライアント領域アニメーション設定の尊重を候補に含める。無効化しても会話機能は継続する。追加メニューの文言と既定値は合意時に確定する。

## 3. 待機・優先度・割り込み

制御はWPFの表示処理から分離し、Idle、Playing、Suspended、Disposedの状態を持つ案とする。受信・送信の成否を、この再生状態から逆算しない。

| 優先度 | 入力 | 再生時の扱い |
| --- | --- | --- |
| 最優先 | 終了・再起動・左押下／ドラッグ・設定メニュー・サイズ変更 | 即時停止。終了は以後の要求を拒否、操作は基準姿勢に戻す |
| 60 | 新規受信 | 低い演出を置換。受信が続く場合は最新の1件分だけ保留 |
| 50 | 確定した失敗（採用時） | 低い演出を置換。新規受信より優先しない |
| 40 | 新しいローカル送信の受理確定 | 低い演出を置換。受信中は最新の1件だけ保留 |
| 30 | クリック成立 | 会話開閉を優先して短く再生。保留しない |
| 10 | 本体内の視線（採用時） | 他の演出がなければ表示。保留しない |
| 0 | 待機 | 他の要求がなければ再生 |

再生中1件＋保留最大1件とし、保留には単調時計で2秒の有効期限を設ける。高い優先度を保持し、同じ優先度では新しい要求に置き換える。期限切れ・停止した演出は再開せず、必要なら新しい要求を再評価する。複数メッセージをまとめても履歴・新着IDは全件処理する。

操作による一時停止中は、送受信の新しい要求だけ最大1件保持できる。操作終了後に有効期限内のものだけ再生する。クリック・視線の後追い再生はしない。同一クリックの動作は800ms程度の間隔、受信は1回の完全読込単位でまとめる初期案とする。

古い完了通知が新しい演出をidleへ戻さないよう、再生の世代番号またはキャンセルトークンで完了を照合する。描画エラー時は動作機能だけを停止し、元の立ち絵と会話機能に戻る。

## 4. 新規メッセージを確定する境界

現行の接点は [MainWindow.Conversation.cs](../../src/HagoromoChan.Desktop/MainWindow.Conversation.cs) のReadMessagesAsync、AddMessage、SendMessageAsync、ObserveRepliesである。AddMessageはsequenceで重複挿入を防ぐが、それ自体を「新着アクション」の条件にしない。

### 受信

1. 初回はHasMore=falseまでの成功で基準を作り、受信演出を出さない。初回の途中失敗後も基準作成が完了するまでは同じ扱い。
2. 以後は最後に完全読込が成功した通知基準より後、今回の確定カーソル以下にあるassistant発言をIDとsequenceで識別する。受信の対象は通常返信・能動発言とも同じ。
3. 途中ページは既存の会話取込処理を進められるが、演出の基準は全ページ成功まで進めない。途中で挿入済みになった発言を、次回のAddMessage=falseだけを理由に取りこぼさない。
4. 通知対象を確定して基準を進めた後、再生側へ不変の通知を渡す。再生要求の期限切れ・失敗を理由に同じ受信を再通知しない。
5. 再起動の最初の同期、未読の復元、履歴を開く、既読の変更では再生しない。再起動中の未読復元と今回起動後の新規受信を分ける。
6. カーソル逆転や基準IDの不一致は新着とみなさない。既存の通信エラー処理へ戻す。DB交換・復旧の変更はM06の責務として切り分ける。

未読件数・保存済みUnreadIds・本文の時刻を、新規イベントの唯一の判定根拠にしない。アクションの基準はプロセス内で持ち、会話DB・未読設定へ演出済みフラグを追加しない。

### 送信

この起動中にユーザーが新規作成した要求を登録し、保存済みrequest ID・本文との一致を確認した受付結果、または後続ポーリングでの一致確認を契機に一度だけ通知する。再試行のHTTP成功、FinishAcceptedMessageの後処理、pendingファイル削除の再試行では再通知しない。前回起動から復元したpendingは既定で対象外とする。

送信受付の通知は「Relayに保存された」段階だけを表し、Dotへの配信・Dotの実行・回答完了を意味しない。すぐ返信が届いた場合は受信反応を優先し、送信反応を長く続けない。

## 6. 素材形式と管理

[素材確認記録](M09-mini-asset-review.md)のA案を推奨候補とし、現在の立ち絵の絵柄でMiniの仕草を再現する。既存Miniパックを利用するB案も選べるが、どちらを採用するかは未確定。

制作単位は「1キャラクター／絵柄のパック → 1アクション → 同じキャンバスの透過PNGコマ列」とする。編集用マスター・制作メモを原本として残し、実行用には透過PNGアトラス＋JSONを出力する案。単体PNGコマ列を入力にできるようにし、アトラスだけが原本になる構成を避ける。GIF/MP4はレビュー用のプレビューと位置付ける。

JSONは版、パックID、対応する基準立ち絵、共通キャンバス、足元アンカー、各動作の矩形・有効コマ・コマ時間・繰り返し・終了先を宣言する。イベントへの割当てと優先度は別の設定に置き、素材差替えで通信の意味や操作規則が変わらないようにする。

既存Miniの8列×11行、192×208セルを読み取れる矩形定義を持たせる。新規素材にMiniの11行固定や英語名を必須とせず、追加の動作IDを登録できるようにする。素材にコード、任意XAML、外部ネットワーク参照は含めない。

検証は宣言版、PNG形式、画像寸法、矩形の範囲、有効コマ、正の有限時間、共通アンカー、透明領域、総展開メモリ上限を確認する。初期候補は1パック128MiB以下の展開画素、1動作64コマ以下、1コマ50～1000ms。正確な上限は必要素材を計測してから確定し、読込前に総画素数を見積もる。73コマのMiniパックを誤って「1動作64コマ超」と拒否しない。

実行用素材はDesktopのAssets/Reactionsに同梱する案。任意差替えはデータディレクトリ内のreactions/<pack-id>に置き、pack.jsonで宣言した相対PNGだけを参照する。絶対パス・親ディレクトリへの逸脱は拒否する。既存mascot.pngを使用中なら、それに対応することが確認できない同梱パックは適用せず静止画へ戻す。パックの破損で会話を停止しない。

## 7. 描画・サイズ・操作の整合

- アクションの足元と共通キャンバスを固定し、コマごとに透明余白を自動トリミングしない。ジャンプはキャンバス内の絵だけを動かす。
- 既存の高さ120/180/260 DIP、モニターDPI、作業領域、原寸以上に拡大しない上限を維持する。必要な動作余白はパック全体で設計する。
- 各フレームでWindow.Left/Top/Width/Heightや吹き出しの配置を変更しない。画像差替えだけでCheckPlacementや位置保存を呼ばない。
- 操作判定用の固定面と描画画像を分ける案。画像の変形・コマ切替がクリックの成否やドラッグ開始点を動かさないようにする。完全透過部分で背後を操作できることはWindowsで実測する。
- PNGは起動時またはパック切替時に読み、再生中にファイルを毎コマ開かない。WPFのBitmapSourceを再利用し、再生時に会話面を作り直さない。
- フレーム選択はUI Dispatcher上で行う。タイマーは処理遅延がある前提で単調時計の経過から現在コマを選び、遅延分を高速連続再生しない。待機・停止時は不要な更新を止める。
- 追加の軽い変形が必要ならRenderTransformを候補とする。LayoutTransformで会話レイアウトを再計算する方式は採らない案。
- 終了・再起動受付、PrepareShutdown、描画面破棄でタイマー、完了通知、イベント購読、アニメーションを解除する。M08の管理終了を待たせない。
- M10は将来の移動判断・目的地・経路・座標保存を所有し、M09は移動方向に応じた再生要求を受ける接点だけを用意できる構成にする。具体APIはM10設計時に確定する。

技術的な根拠: [WPF変形](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/transforms-overview)、[アニメーション](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/animation-overview)、[DispatcherTimer](https://learn.microsoft.com/en-us/dotnet/api/system.windows.threading.dispatchertimer?view=windowsdesktop-10.0)、[ClientAreaAnimation](https://learn.microsoft.com/en-us/dotnet/api/system.windows.systemparameters.clientareaanimation?view=windowsdesktop-10.0)。候補方式の根拠であり、当アプリでの動作検証ではない。
