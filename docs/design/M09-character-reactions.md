## 1. 今回の到達点と前提

羽衣ちゃんの動きを、既存Miniの仕草を参照してWPFの立ち絵上で再生する。M09は姿勢と視線を担当し、自律的なウィンドウ移動はM10に残す。

新着の基準はM04から引き継いだ。初回履歴・再取得・履歴閲覧を除き、通常返信と能動発言を共通に扱う。以下の再生時間と目線の強さは今回の候補値で、実機で見え方を確認する。

引継ぎ元の末尾「M10の自律移」は、mainのM09/M10定義とも整合する「自律移動への拡張性・責務分離」として暫定解釈する。元の開発会話にある開始用プロンプト案にも拡張性の記述があるが、途切れた依頼の未受領部分を追加指示とみなさない。

## 2. 状況とアクションの対応

表に示した素材名とコマ数は、スペースの「画像」にある[デフォルメ版の一覧](M09-mini-asset-review.md)に基づく。コマ数は有効枠の数で、再生速度はWPFで調整する。原画寄りの版も参照したが、コマ単位の確認はデフォルメ版で行った。

### 基本の動き

| 場面 | 羽衣ちゃんの動き | 選んだ理由・操作との関係 |
| --- | --- | --- |
| E01 未読・回答待ちのない通常待機 | 正面でまばたきする `idle`（6コマ）を繰り返す | 普段の姿を一定にすると、手振りやジャンプの始まりに気付きやすい。初回履歴の読み込みが完了すると、既存の未読状態に応じて待機姿勢が切り替わる。 |
| E06 この起動中に送ったメッセージをローカルRelayが受け付けた | `review` で一度手元に視線を落とし、E07の返信待ちへ | 預かった文を受け付けたことが分かる。同じ送信の再確認では繰り返さない。 |
| E08 新しい通常返信・能動発言が届いた | `jumping`（5コマ）でその場で一度小さく跳ね、回答待ち・未読あり・通常待機の順で次の姿勢を選ぶ | 送信時の小さな仕草と見分けやすく、本文の内容に関係なく到着に気付ける。絵だけを動かし、ウィンドウと吹き出しの位置は保つ。 |
| E03 会話の吹き出しを開く・閉じる | 本体クリックで開くときは従来の `waving`。最後の吹き出しを閉じたときは `farewell` で胸の脇に手を低く上げ、手首だけを小さく一度振る。 | 演出中でも次の操作を受け付ける。履歴・入力の一方が残るときや自動非表示では別れの手振りを出さない。 |
| E04 左ボタンを押している間・ドラッグ中 | 待機の基準姿勢を保つ。移動後のボタン解放・キャプチャ喪失では手を振らない | 押した位置とつかんでいる絵がずれない。移動せずに離して既存のクリック判定が成立した時だけE03へ進む。 |
| E05 右クリックメニューを開いている間 | 基準姿勢を保つ | サイズ変更や終了などの項目を落ち着いて選べる。メニューを閉じただけでは挨拶を始めない。 |

単発動作は、送信受付0.8秒、新着0.65秒、開く手振り0.6秒、閉じる手振り0.7秒。標準立ち絵のまばたきは約4.8秒に一度で、閉眼は150ms。

### 待機、視線、操作の例外

| 場面 | 扱いと理由 |
| --- | --- |
| E02 カーソルが本体に近づく、または羽衣ちゃんの会話・状態パネルを操作する | 本体の表示枠から96 DIP以内に約0.3秒留まると顔を向け、120 DIPまで追い続ける。履歴スクロール・入力などの操作時は距離や待ち時間によらず、その時のカーソルの方向を向く。 |
| E07 送信後、返信を待つ | 受付の仕草が終わったら、顎に指を添えて考える。肩と足を据えたまま、指を添えた側へ首を最大5.5度かしげる。少しそのまま考えてから正面に戻り、約4.6秒で一周する。E02のカーソルや動いたウィンドウへ一時的に顔を向ける。新着には一度跳ね、未回答があれば考える姿勢へ、すべての返信が届いたら未読の有無で待機姿勢を選ぶ。 |
| E09 送信前の保存失敗・明示的な受付拒否 | 確定した失敗では短くうつむく。タイムアウトや通信結果不明時は既存UIで再確認する。 |
| E10 初回履歴・同一メッセージの再取得・履歴閲覧・既読操作・入力中のIME変換 | 履歴操作・入力ではE02の視線を使う。過去のメッセージへの受信ジャンプは再生しない。履歴表示中や入力中に本当に新着が届けばE08を適用し、フォーカスは移さない。 |
| E14 回答待ちがなく、新着表示に未読が残っている | 片手を胸元に添えて正面に微笑む。7秒のうち最後の1秒だけ、表示中の未読の吹き出しへ目を向ける。吹き出しが表示されていない時は、表示中の「新着」ボタンを見る。どちらも隠れていれば正面を向いたまま。 |
| E11 正面の作業姿勢、E12 左右への走行 | `running` は実際の作業開始を観測できる場合の候補。`running-left` と `running-right` はM10の移動方向に合わせる候補。今回の基本反応はその場で完結する。 |
| E13 終了・再起動が受け付けられた | 再生を停止し保留を破棄する。M08が直ちに終了処理へ進める。 |

右クリックの「キャラクターの動き」から次の動作を選ぶ。選択は保存され、次回起動にも引き継ぐ。

| 選択 | 動作 |
| --- | --- |
| Windowsに合わせる（現在はオン／オフ） | 初期値。Windowsのアニメーション設定に従う。従来のオン設定もこの扱いになる。 |
| 常に動かす | Windowsの設定にかかわらず、羽衣ちゃんだけを動かす。 |
| 動かさない | 静止表示を維持し、視線用のウィンドウ観測も止める。従来のオフ設定を保持する。 |

## 3. 待機・優先度・割り込み

再生はWPFから独立した [CharacterReactionState](../../src/HagoromoChan.Desktop/CharacterReactionState.cs) が制御する。単調時計で動作を進め、操作中は停止し、終了時は保留を破棄する。

| 優先度 | 入力 | 再生時の扱い |
| --- | --- | --- |
| 最優先 | 終了・再起動・左押下／ドラッグ・設定メニュー・サイズ変更 | 即時停止。終了は以後の要求を拒否、操作は基準姿勢に戻す |
| 60 | 新規受信 | 低い演出を置換。受信が続く場合は最新の1件分だけ保留 |
| 50 | 確定した失敗 | 低い演出を置換。受信が優先 |
| 40 | 新しいローカル送信の受理確定 | 低い演出を置換。受信中は最新の1件だけ保留 |
| 30 | 開閉の挨拶 | 本体で開くときは大きな手振り、最後の会話面を明示的に閉じたときは小さな手振り。同じ挨拶を保留しない |
| 10 | 通常・未読・返信待ち中の視線 | カーソルへの視線を優先し、追従後はその時の姿勢に戻る。未読待機での吹き出しへの視線は1秒間。残りの6秒では動いた外部窓への従来の反応も有効 |
| 0 | 待機 | 回答待ち、未読あり、通常の順で再生 |

再生中1件＋保留最大1件とし、保留には単調時計で2秒の有効期限を設ける。高い優先度を保持し、同じ優先度では新しい要求に置き換える。期限切れ・停止した演出は再開せず、必要なら新しい要求を再評価する。複数メッセージをまとめても履歴・新着IDは全件処理する。

操作中は直近の送受信を最大1件まで保留する。解除後、期限内のものだけ再生する。同じ向きの挨拶は800ms以内の連続再生を抑え、すぐに開閉を反転した時は新しい操作に切り替え、受信は1回の完全読込単位でまとめる。

閉じる挨拶は、本体クリック・吹き出しの×・最後の入力面でのEsc・右クリックメニューから最後の会話面を閉じたときに一度だけ行う。メニューを開いて閉じただけの場合、IME変換中のEsc、表示が変化しなかった場合、ドラッグ、アプリ終了では再生しない。受信・送信受付・失敗の途中に本体を押した場合、押下中は基準姿勢で止まり、成立した閉じるクリックでは元の動作の残り時間を優先する。押下中に期限が切れた動作は再開しない。

終了コールバックを動作ごとに予約せず、現在の動作と開始時刻から次のコマを求める。描画エラー時は静止画へ戻る。

## 4. 新規メッセージを確定する境界

現行の接点は [MainWindow.Conversation.cs](../../src/HagoromoChan.Desktop/MainWindow.Conversation.cs) のReadMessagesAsync、AddMessage、SendMessageAsync、ObserveRepliesである。AddMessageはsequenceで重複挿入を防ぐが、それ自体を「新着アクション」の条件にしない。

### 受信

1. 初回はHasMore=falseまでの成功で基準を作り、受信演出を出さない。初回の途中失敗後も基準作成が完了するまでは同じ扱い。
2. 以後は最後に完全読込が成功した通知基準より後、今回の確定カーソル以下にあるassistant発言をIDとsequenceで識別する。受信の対象は通常返信・能動発言とも同じ。
3. 途中ページは既存の会話取込処理を進められるが、演出の基準は全ページ成功まで進めない。途中で挿入済みになった発言を、次回のAddMessage=falseだけを理由に取りこぼさない。
4. 通知対象を確定して基準を進めた後、再生側へ不変の通知を渡す。再生要求の期限切れ・失敗を理由に同じ受信を再通知しない。
5. 再起動の最初の同期、未読の復元、履歴を開く、既読の変更では再生しない。再起動中の未読復元と今回起動後の新規受信を分ける。
6. カーソル逆転や基準IDの不一致は新着とみなさない。既存の通信エラー処理へ戻す。DB交換・復旧の変更はM06の責務として切り分ける。

未読件数・保存済みUnreadIds・本文の時刻を、新規イベントの唯一の判定根拠にしない。アクションの基準はプロセス内で持ち、会話DB・未読設定へ演出済みフラグを追加しない。

### 送信

この起動中にユーザーが新規作成した要求を登録し、保存済みrequest ID・本文との一致を確認した受付結果、または後続ポーリングでの一致確認を契機に一度だけ通知する。再試行のHTTP成功、FinishAcceptedMessageの後処理、pendingファイル削除の再試行では再通知しない。前回起動から復元したpendingは既定で対象外とする。

送信受付の通知は「Relayに保存された」段階だけを表し、Dotへの配信・Dotの実行・回答完了を意味しない。すぐ返信が届いた場合は受信反応を優先し、送信反応を長く続けない。

## 5. M04から引き継いだ受信条件と実装の分担

[M04実装候補の設計](https://github.com/eckolo/HagoromoChan/blob/4e63273869188e629683092a7c090b4e0b5eca06/docs/design/M04-proactive-messages.md#L52-L60)とユーザーが引き継いだ条件に従う。通常返信・能動発言ともに `Role == "assistant"`。能動発言は `InReplyTo == null` かつ `Id` が `proactive_` で始まる。これらは履歴上の識別に使えるが、M09の受信演出は両者共通のE08とする。

M04は送信経路・永続化と、Desktop側では `DesktopPanels.cs` の履歴見出しを担当する。M04の候補は `MainWindow.Conversation.cs`、`MainWindow.Interaction.cs`、`MainWindow.xaml.cs` を変更しない。

M09は `ReadMessagesAsync` の全ページ取得後、今回確定したassistant行を `ReactionInbox` で抽出し、まとめて `Receive` に渡す。通常返信と能動発言が1件ずつ同時に届いた場合、通知対象は2件、ジャンプは1回。同じ2件の再取得ではどちらも0回。履歴を表示中に新しいIDが届けば反応する。

既存の `ChatMessage` をそのまま受け取る。`Id` と `Sequence` で新着を識別し、`InReplyTo` で対応する返信待ちを解除する。M04の公開型やイベントには変更を加えない。

未読待機は既存の `DesktopPreferences.UnreadIds` を読み取る。初回の完全な履歴照合後、保存済みの未読はジャンプを伴わず胸元の姿勢になる。履歴の再取得、未読の追加、複数のうち一部の既読化では未読が続く間の7秒周期を保つ。最後の未読が解除されると通常待機に戻る。M14が担当する未読の解除条件と保存形式は従来のまま。

M04はmainへ先行統合済み。M09は作業枝上で受入を受けた後、最新mainとの結合・回帰を経て2親マージする。

## 6. 描画と差し替え素材

目が細く見えるという実機での所見を受け、同梱立ち絵をもとに、全身を描き直した[9姿勢のシート](../../src/HagoromoChan.Desktop/Assets/MascotReactions.png)を作成した。見上げる時は顎を上げ、左右を見る時は顔と肩も対象へ向ける。斜め方向の境界付近では直前の向きを保ち、細かな位置変化で絵が往復するのを防ぐ。標準絵は上下左右の4方向、独自パックは従来の16方向を扱う。コマの透明余白と足元の基準を揃え、待機・ドラッグ・動作オフの姿勢に同じ正面絵を使う。

標準の[思案の元絵](../../src/HagoromoChan.Desktop/Assets/MascotThinking.png)には通常待機と同じ頭髪・目・顎の輪郭を使う。表示時は胴・頭・手の3枚をこの順に重ねる。胴と肩を固定し、頭の画像を首の付け根まわりに等倍で回す。手の画像は顎の接点が動いた分だけ平行移動する。各画像の寸法と基準点は[素材説明](../../src/HagoromoChan.Desktop/Assets/README.md)に記載した。

独自パックはデータフォルダーの `reactions/default/pack.json` と透過PNGで指定する。キャンバス、足元の基準点、各コマの左上と時間を宣言する。例えば192×208のシートで2つの待機コマを切り出す最小構成は次の通り。

```json
{
  "version": 1, "baseArtwork": "bundled",
  "canvasWidth": 192, "canvasHeight": 208, "anchorX": 96, "anchorY": 200,
  "actions": {
    "idle": { "frames": [
      { "file": "sheet.png", "x": 0, "y": 0, "durationMs": 750 },
      { "file": "sheet.png", "x": 192, "y": 0, "durationMs": 250 }
    ] }
  }
}
```

`idle` は必須。`review`、`jumping`、`waving`、`farewell`、`waiting`、`thinking`、`unread`、`failed` を同形式で追加できる。`look` は右を0番として時計回りに16方向を定義し、カーソルや動いた窓を向く時に優先する。静かな回答待ちには `thinking` のコマ列を一周4.6秒で再生する。未定義の場合は `waiting` のコマ列、`look` の方向絵、`idle` の順で利用する。フレーム時間はその動作の再生時間内での各コマの占有比になる。1動作最大64コマ、各コマ50〜1000ms、パックの展開見積りは128MiBまで。単体PNGなら各コマの座標を0,0とする。原寸を超えて拡大しない。 `unread` を用意した独自パックは7秒周期でそのコマ列を再生し、従来のパックは `idle` の1秒周期を保つ。 独自パックの `farewell` は任意で、未定義なら `idle` を表示する。

独自の `mascot.png` を使うときは `baseArtwork` にそのファイルのSHA-256（16進）を指定する。対応パックがなければ独自絵のまま静止する。不正なパックでも会話できる。実装は [CharacterReactionPack](../../src/HagoromoChan.Desktop/CharacterReactionPack.cs) と [標準立ち絵の描画](../../src/HagoromoChan.Desktop/BundledReactionDrawing.cs) にある。

## 7. 視線とウィンドウ操作

[CursorGaze](../../src/HagoromoChan.Desktop/CursorGaze.cs) はカーソルから本体の表示枠までの最短距離を、本体のある画面の表示倍率で補正する。追い始める距離と追い終わる距離に差を設け、境界で正面と横顔が頻繁に切り替わるのを防ぐ。

[会話・状態パネルの入力処理](../../src/HagoromoChan.Desktop/MainWindow.PanelInput.cs) はクリック、ホイール、左ボタンでのドラッグ、キー・文字入力、履歴ボタンの長押しを拾う。最後の操作から1秒間、カーソルの現在位置を追い、連続操作で延長する。パネルの自動更新や遠くのパネルにカーソルを置いただけでは始まらない。送信受付・新着・手振りなどの専用動作が優先される。他のアプリ内の入力は購読しない。

[WindowActivityGaze](../../src/HagoromoChan.Desktop/WindowActivityGaze.cs) は、可視の外部ウィンドウの位置・大きさを約300ms間隔で比較する。移動・サイズ変更、前面への切替、新規出現の順に対象を選び、最後の変化から約1.5秒で注視を解く。対象の中心を物理画面座標で求めるので、左側のモニターも扱える。窓の内容やタイトルは取得しない。窓を固定したまま再生する動画やページ内スクロールは対象外。

操作と描画には同じ固定キャンバスを使う。コマの変更ではウィンドウ位置、吹き出し、入力フォーカスを動かさない。ドラッグ・メニュー中は基準姿勢で停止する。表示は小120・中180・標準260 DIPと原寸上限を引き継ぐ。設定OFF・終了時にタイマーを止め、終了時にはイベント購読も解除する。結合箇所は [MainWindow.Reactions](../../src/HagoromoChan.Desktop/MainWindow.Reactions.cs) にまとめた。

## 8. 検証と受入

新着判定、待ち合わせ、動作の優先順位、期限切れと停止は回帰テストの対象とする。Windows上の見た目、実ウィンドウへの追従、ドラッグ、IME、透過部分のクリック、サイズ・DPIは実機で確認する。実施済みと残項目は[検証記録](../operations/M09-verification.md)、進捗とブランチ情報は[M09個別記録](../milestones/M09.md)を参照。受入後に最新mainを取り込み、必要な回帰を経て2親マージする。
