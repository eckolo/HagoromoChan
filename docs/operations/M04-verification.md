# M04 実機・回帰確認手順

対象: [M04](../milestones/M04.md) / [設計](../design/M04-proactive-messages.md)。
既存のM08管理起動を使用。会話履歴・購読・キーを削除したり、新規プロファイルを無条件作成したりしない。M09の未統合成果と混ぜず、M04固定版を確認する。

## 1. ローカル検証・配置

リポジトリルートから未コミット変更を保護したうえで、初回は次の作業枝を取得する。

    git status --short
    git fetch origin
    git switch --track origin/milestone/M04-dot-proactive-messages

既存のローカル枝なら git switch milestone/M04-dot-proactive-messages と git pull --ff-only を用いる。Git操作は利用者への通常の再試行案内では省略可とし、この手順書には残す。

回帰検査（隔離DB、ローカルテスト用）:

    dotnet run --project .\tests\HagoromoChan.Tests --configuration Release

通常の更新・配置:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Update.ps1

Relayを変更するため全体ビルド。保存済みConfigure設定と既存購読をそのまま利用する。起動後、接続状態を確認する。トンネル障害時はM08の診断手順を参照。

## 2. プラグインの新ツール確認

公式のプラグイン詳細画面から接続／ツールメタデータの更新（Refreshなど、現在のUI表記に従う）を実施し、既存HagoromoChanに send_message が追加されたことを確認する。既存 get_context / reply と message.created を維持。新しいツールの書き込み権限・承認が求められた場合は内容を確認し、必要な範囲のみ許可する。プラグインの削除・再作成や購読の無条件再登録は行わない。更新機能は[公式ガイド](https://developers.openai.com/plugins/build/app-quickstart)を参照。実アカウントでのUI・認識・権限は未確認。

## 3. 既存Dotでの直接テスト

Windowsアプリから対応する発言を送信せず、羽衣ちゃんの既存ChatGPT会話で更新済みプラグインを利用して次の内容を依頼する。

> HagoromoChanのsend_messageで、channel_idはhagoromo-mini、発言IDは新しい非ゼロUUIDを1つ生成し、「M04：能動発言の受信テストです。」をWindowsアプリへ送ってください。この発言はWindowsの依頼に対する返信ではありません。replyは使わず、結果が不明な場合は同じIDと本文で再試行してください。保存結果を報告してください。通常の操作承認条件を守ってください。

Windows側で「羽衣ちゃん・自発」と本文が表示されること、履歴に保存されること、送信待ち・返信待ちの件数が意図せず変化しないことを確認する。同じIDと本文で再試行して1件のままか、別本文は拒否されるかを確認する。承認要否やツールが見えない場合は結果を記録し、権限を無断で拡張しない。このテストは対応するWindows依頼がないことの確認であり、Dotの自律実行の証明ではない。

## 4. 承認済みの一回タスク（前段成功後）

ユーザーが希望する場合に限り、羽衣ちゃんの既存Dot会話で、本人が操作承認を確認したうえで一回限りの将来のタスクに send_message を組み込む。Windowsアプリとトンネルを稼働させ、予定時刻にユーザーが新たな発言をせずに受信できるか、承認要求・実行履歴・ツール結果を確認する。予定時刻の実行、ツール利用、再配送の可否は未確認。繰り返しタスクや常時動作はこの検証では設定しない。失敗時には状況を記録し、同一ID・本文で重複防止を維持する。
