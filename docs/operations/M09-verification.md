## 1. 対象版と準備

正式な検証ではGitの対象版を明記する。ユーザー向けの通常の操作案内では、Git操作を省いた実機確認項目を別途提示できる。

1. 作業中の変更がないことを確認し、既存変更を捨てない。
2. リポジトリのルートで次を行い、M09の確認対象SHAを記録する。進行中の別担当のブランチは切り替えて編集しない。

```powershell
git status --short
git fetch origin
git switch milestone/M09-character-reactions
git pull --ff-only origin milestone/M09-character-reactions
git rev-parse HEAD
```

3. Windows 11、.NET 10 SDK、DPI・画面作業領域・モニター構成を記録する。
4. 認証情報・実会話・個人設定をGitに保存しない。素材・制御の検査は合成メッセージと検証用データで行い、実運用のDB・購読を変更しない。
5. 稼働中の配置へ直接上書きせず、M08の既存Build.ps1で新しい候補を作る。実運用への配置・再起動は別段階で扱う。

実装後のビルド・回帰実行例:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1
dotnet run --project .\tests\HagoromoChan.Tests\HagoromoChan.Tests.csproj --configuration Release
```

Build.ps1は候補をapp-stage-*に作る現行方式であり、この例だけで配置更新・アプリ再起動は行わない。未統合のM04を組み合わせる前に、固定SHAと必要範囲を記録し、管理規則に従う。

## 2. 自動回帰で確認する性質

既存のテスト実行器はWPFに依存しないDesktopロジックをリンクして検証している。M09の独立した判定・制御も同じ考え方で検査し、WPFの見た目の合格とは区別する。

| ID | 入力 | 期待する性質 |
| --- | --- | --- |
| A01 | 初回履歴を複数ページで取得。途中で一度失敗し再取得 | 全ページ成功で基準作成だけ。履歴への受信演出0回 |
| A02 | 基準作成後、返信と能動発言を複数ページで取得。途中失敗後に成功 | 途中で挿入済みでも通知対象を失わず、完全成功後に各IDを一度だけ対象化 |
| A03 | 同じIDの再取得、未読の復元・解除、履歴開閉、再起動 | これらだけで動作を再発生させない |
| A04 | 新規送信のPOST成功、結果不明後の同ID再試行／ポーリング確認、pending整理失敗 | 新規の受付確定は1回。前回起動からのpending復元は対象外 |
| A05 | POSTで先行挿入したuser行のsequenceが読込カーソルより先 | 完全読込の基準を早めず、別のassistant発言を失わない |
| A06 | カーソル逆転、基準のID不一致 | 新着として演出せず、既存の異常処理を維持 |
| A07 | 低・高・同じ優先度、連続受信、期限切れ、遅れて届く旧完了通知 | 再生中1件＋保留最大1件。高い要求を優先し、古い通知が新しい動きを止めない |
| A08 | 左押下、ドラッグ閾値、キャプチャ喪失、右クリック、終了要求 | 操作の成立を変えず再生を停止。終了後は新規要求を拒否 |
| A09 | PNG破損、無効矩形、未使用セル、時間異常、過大メモリ、パス逸脱、不適合パック | 読込を拒否し静止画へ戻る。通信・履歴に副作用を起こさない |
| A10 | 同じパック内で全コマ、サイズ・DPIの変化 | 共通アンカー・原寸上限を満たす。フレーム切替だけでWindow座標を保存しない |

## 3. Windowsでの確認

| ID | 操作・条件 | 観察・記録すること |
| --- | --- | --- |
| W01 | 初回起動、過去の未読を含む再起動 | 待機は表示される。過去の返信を受信したように跳ねない |
| W02 | 通常クリック、連打、開閉、入力中・IME変換中の新規受信 | 会話開閉・下書き・フォーカスを維持。反応は短く終わる |
| W03 | 閾値前の手ぶれ、ドラッグ、キャプチャ喪失、画面端、負座標、異なるDPIの画面への移動 | 押下点・移動・クリック判定が動作でずれない。ドラッグ終了でクリック反応を出さない |
| W04 | 右クリック、メニューを閉じる、サイズ変更・最前面設定 | 設定操作を優先。解除後に古い反応を大量再生しない |
| W05 | 新規送信成功、結果不明、同ID再確認、確定した保存失敗／受付拒否 | 受理・配信・回答を混同しない。再試行が演出を重複させない |
| W06 | 通常返信、M04の能動発言、連続受信、途中読込失敗 | 完全成功後に短く反応。すべての発言が保存・閲覧でき、新着IDを失わない |
| W07 | 小120・中180・標準260 DIP、100/125/150/200% DPI、両素材方針 | 画質、足元、透明余白、ジャンプの上端、原寸上限。吹き出しの位置がコマで揺れない |
| W08 | 完全透過部分、キャラクター境界、動作中のクリック | 背後のデスクトップ操作と本体の操作可能性を実測。透明な操作面が広がりすぎない |
| W09 | 素材欠損・破損、mascot.png差替え、動き無効、Windowsのアニメーション設定変更 | 静止画で会話を継続。対応のない絵柄が混在しない |
| W10 | 動作中・保留中に終了、再起動、管理停止 | 動作待ちが終了を遅らせない。タイマー・完了通知・プロセスが残らない |
| W11 | 待機と連続受信の一定時間観測 | CPU・メモリ・UI応答、画像の毎コマ読込の有無、不要なレイアウト・位置保存の有無。基準値と候補値を同じ条件で比較 |

M04結合は受信機能自体の実機確認とM09の反応確認を分けて記録する。能動発言を人工のassistant行で再現した検査を、実際のDotからの能動発言成功とは扱わない。
