## 着手順と依存

- M01 はアプリの必須機能であり、最優先で基本 UI を実用段階に進める。M02～M04 は原則その後に検討する。M01 の完了自体を一律の技術的依存とはせず、完了前の並行着手は必要性を整理しユーザーと合意する。
- M02 と M03 の優先度は同じ（中）。両者間の順序・技術依存は現時点で定めない。M04 は低。依存が判明した場合は記録して調整する。
- 4件の名称・目的・優先度はユーザーの提示に基づく。詳細な仕様・完了条件は着手時に確定する。個別記録の完了条件は暫定案であり、未承認の仕様追加を意味しない。
- 既存の通信実証は現行実装の成果として扱い、新たなアプリ本体マイルストーンにはしない。

## 更新方針

- 管理系 ID は `MGMT-01` 形式、今回のアプリ本体は `M01`～`M04` とする。新規 ID は重複させない。
- ID は登録後に原則変更・再利用しない。名称変更や範囲変更は個別記録に履歴を残す。
- 優先度は着手順の目安、依存関係は着手・統合の条件として別々に扱う。依存グラフに循環を作らない。
- 新規登録時はユーザーと合意した目的、範囲、完了条件、依存関係を個別文書に定義する。未確定事項は明記する。
- 完了済みの行も履歴として残す。追加・修正・登録は管理系等のマイルストーンのマージで反映する。
