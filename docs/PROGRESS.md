## 次の作業

M03・M08はユーザー受入と各完了マージによって一区切りとする。残検査は個別記録・実機確認手順に維持する。M04を高優先度の次の主着手候補、M09を中優先度の早期並行着手候補とする。M04は能動発言の通信・記録・表示経路、M09は表示・演出・再生制御を担当し、既存のメッセージ確定・受信イベント境界で接続する設計を検討する。同じファイルを同時に編集せず、別枝で作業し、mainへの統合は直列に行う。M04を先に統合する案を優先し、M09は最新main取り込み後に通常返信・能動発言とマウス操作の結合回帰を行う。M06は緊急性低下により中へ変更するが範囲は維持する。M05も中、M10・M14は低。M04/M09の実装着手・実際の並行実行はまだ行わず、指示後に開始する。

## 更新ルール

- 状態定義と運用は [開発運用手順](operations/development-workflow.md) に従う。
- 途中進捗は各作業枝の個別記録を更新する。全体報告時は main の一覧と各枝の最新記録を突き合わせて集約する。
- main の一覧は完了マージ等の確定点で更新する。直接コミット、途中公開用の fast-forward 統合を行わない。
- ユーザー側の対応が必要なら具体的な依頼、担当、再開条件を記載する。
- 完了マージの存在・親関係・読戻し結果を確認する。候補上の完了表示はマージ成立前には効力を持たない。
