## 次の作業

M03・M08・M04はユーザー受入と各完了マージによって一区切りとする。残検査は個別記録・実機確認手順に維持する。M04の能動発言受信経路と回帰35/35成功を確認し、日次定例は完了判定外の運用確認とする。問題が発生した場合のみユーザーが別途マイルストーンを提示する。M09は自身の作業枝の最新記録に従い、M04を含む最新mainを取り込み、通常返信・能動発言とマウス操作の結合回帰を行う。M06は中優先度・未着手を維持する。M05も中、M10・M14は低。

2026-11-26追記（MGMT-16）: M04の実機検証で受領した自動応答停止・購読元接続不一致をM06の障害例と追加完了条件へ反映した。M04/M09の作業状態は各作業枝の最新記録で確認する。M06は中優先度・未着手を維持する。M04の後続実機報告では自動応答が復旧したが、切替操作の個別証跡と原因の確定は未取得であり、M06の検討条件は維持する。

## 更新ルール

- 状態定義と運用は [開発運用手順](operations/development-workflow.md) に従う。
- 途中進捗は各作業枝の個別記録を更新する。全体報告時は main の一覧と各枝の最新記録を突き合わせて集約する。
- main の一覧は完了マージ等の確定点で更新する。直接コミット、途中公開用の fast-forward 統合を行わない。
- ユーザー側の対応が必要なら具体的な依頼、担当、再開条件を記載する。
- 完了マージの存在・親関係・読戻し結果を確認する。候補上の完了表示はマージ成立前には効力を持たない。
